The different IDs allow installing both test apps side by side. These are
armeabi-v7a packages; devices that support only 64-bit applications cannot run
them. Native code targets API 17; package minSdk is 14 and targetSdk is 28.
The resource compiler used android-17 android.jar and build-tools 28.0.3.
Framebuffer used GCC/gnustl_static from NDK r16b; GLES uses its C entry and the
updated static Clutter stack. Core code was compiled with the same NDK's
standalone ARM toolchain through classic mk. Host mk/iyacc/decgen and Limbo
were native Linux tools. The compiled runtime contains 5752 staged files.

Before launch, grant the test app shared-file access in Android settings.
Runtime assets are provisioned directly into /sdcard/Inferno. Existing files
are preserved; neither app uses an internal runtime tree. Shared-storage access
is subject to the device's Android policy and is not certified for every release.
Existing startup configuration is preserved, so it can affect either test app.
The test-key APKs do not replace an existing differently signed production app.

## Galaxy S25 / Android 16 installation result

The user reported that both packages download but are rejected by the package
installer on a Samsung Galaxy S25 running Android 16. Both artifacts contain
only ELF32 ARM/armeabi-v7a. Samsung documents that Galaxy S24 and newer devices
support only 64-bit apps. These artifacts are incompatible with that device.
The generic installer dialog supplies no ADB error code, but the ABI mismatch
is independently confirmed from the actual APKs and native ELF headers.

Do not treat these as Galaxy S25 test packages or relabel their directories as
arm64-v8a. A usable replacement requires a complete native ARM64 emulator port,
coherent managed-frame/builtin interfaces and rebuilt ARM64 graphics dependencies.
The current arm64 mkfile is only a toolchain profile, not that finished port.

Run tools/verify-apk-abi.py FILE.apk --abi arm64-v8a before presenting a package
for this device. Both current APKs fail that check and pass armeabi-v7a.

https://docs.samsungknox.com/dev/knox-sdk/kbas/kba-1150-sunsetting-32-bit-app-support-on-samsung-devices/
